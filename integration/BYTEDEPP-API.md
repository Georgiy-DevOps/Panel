# VIN и версия системы автомобиля из ByteDepp

Сервер и панель принимают сведения от приложения. В Android-исходниках ByteDepp добавлена отправка при запуске и фоновая задача с интервалом не менее 15 минут при наличии сети. Проверка на реальном автомобиле ещё требуется.

## Запрос приложения

`POST https://84.21.173.88:8443/api/device/session`

Заголовок `Content-Type: application/json`. Пример с вымышленными тестовыми данными, не отправляйте его на рабочий сервер:

```json
{
  "deviceId": "existing-stable-device-id",
  "vin": "L6T79D2D0PP123456",
  "vehicleSoftwareVersion": "ZEEKR OS 6.3.1"
}
```

| Поле | Значение |
| --- | --- |
| `deviceId` | Прежний постоянный идентификатор устройства ByteDepp, до 256 символов. Не менять при каждом запросе. |
| `vin` | VIN, прочитанный приложением с автомобиля: 17 символов, без I, O, Q. Приводится сервером к верхнему регистру. |
| `vehicleSoftwareVersion` | Версия системы автомобиля из достоверного источника на конкретной модели, до 128 символов. Передаётся вместе с VIN. |

`vehicleSoftwareVersion` — версия ПО автомобиля/мультимедиа, которую показывает производитель. Номер Android, версия APK ByteDepp и придуманная версия по VIN не подходят. ByteDepp читает VIN через существующие настройки Geely, Car API или свойство `geely_gpt_vin`. Версия читается через существующий Flyme OTA reader; резервные источники — свойства производителя из `VehicleSoftwareReader`. Поддержку этих источников надо подтвердить на каждой модели. Если прочитать значение не удалось, поле пропускается; тестовые значения не подставляются. Версия Flyme имеет существующий трёхкомпонентный формат для интерфейса; она не является точным идентификатором сборки для выбора boot.img.

Старые запросы с одним `deviceId` или с `deviceId` + `vin` поддерживаются. Пропуск версии сохраняет последнее полученное значение и его исходную дату. Смена VIN на том же устройстве сбрасывает версию предыдущего автомобиля, если новая версия не передана.

Ответ сохраняет прежние поля лицензий и дополнительно содержит:

```json
{
  "vin": "L6T79D2D0PP123456",
  "vehicleSoftwareVersion": "ZEEKR OS 6.3.1",
  "vinReportedAtMillis": 1789560000000,
  "vehicleSoftwareReportedAtMillis": 1789560000000
}
```

Это фрагмент ответа. Временные отметки — время приёма на сервере в миллисекундах Unix. До первого сообщения они равны `null`. `GET /api/license/status?deviceId=...` на том же HTTPS-адресе возвращает эти сведения вместе с существующим статусом лицензии, но не меняет даты получения VIN/версии. Запрос с некорректными полями возвращает 400; тело более 32 КБ — 413.

## Отображение в панели

В разделе «ByteDepp» видны VIN и версия, которые передало приложение. В карточке автомобиля отдельно показан VIN, полученный от ByteDepp. После подтверждения администратором связи автомобиля с устройством клиенту показывается версия этого устройства. При несовпадении VIN версия и сервисы скрываются до проверки. Для устройства без VIN версия не показывается.

Ввод VIN клиентом или администратором регистрирует автомобиль для сопоставления. Он не создаёт показания от ByteDepp. При отсутствии версии панель показывает «Не передана ByteDepp». Ранее введённые вручную версии не используются как данные автомобиля.

Это сведения, сообщённые приложением, а не доказательство владения автомобилем или его текущего онлайна. Подтверждение связи администратором остаётся обязательным для доступа клиента к сервисам.

## Изменения сервера

Скрипт `extend_bytedepp.py` расширяет существующий `bytedepp_server.py`. При запуске сервер добавляет три nullable-колонки в `devices`: `vehicle_software_version`, `vin_reported_at`, `vehicle_software_reported_at`. Лицензии, Telegram-привязки и коды привязки сохраняются. Повторная миграция допустима. Панель читает эту базу только для чтения и работает также со старой схемой.

Android использует WorkManager: отправка при старте, периодическая проверка, повторы после сетевых ошибок. Интервал фоновой работы зависит от ограничений Android; это не постоянное онлайн-соединение. Стабильный `deviceId` сохраняется отдельно и исключён из backup/переноса. Для новой установки он берётся из Android ID, при его отсутствии генерируется UUID. Переустановка, смена Android-пользователя, подписи APK или сброс устройства могут потребовать новой привязки. Ответ сервера проверяется на совпадение deviceId, VIN и переданной версии. Лицензии не активируются автоматически этим кодом.

На машине остаётся проверить фактическое чтение VIN/версии, отправку через HTTPS и появление именно этих значений в админке и нужном клиентском кабинете. До такой проверки подключение реального автомобиля не считается завершённым.

Существующий API device/session не доказывает подлинность устройства. Он не подходит для авторизации прошивки boot.img или иных удалённых команд. Для таких операций нужны отдельные учётные данные устройства, подписанные пакеты и проверенный на конкретной платформе механизм обновления и восстановления.
