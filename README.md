# ByteDepp Control

Панель связывает клиентские VIN с устройствами на существующем сервере ByteDepp. Дополнительное приложение на автомобиль не требуется. Раздела обновлений и установки APK нет.

Репозиторий панели: https://github.com/Kirill-DevSecOps/Panel. Android-изменения ByteDepp ведутся отдельно в https://github.com/DragN1L/ByteDepp, ветка `mane`. Код панели, конфигурация и серверный адаптер не добавляются в репозиторий приложения. Завершённые задачи сохраняются отдельными коммитами и отправляются в соответствующий репозиторий; пароли, базы и ключи в Git не включаются.

## Адреса

- Администратор: https://84.21.173.88:8443/admin
- Клиент: https://84.21.173.88:8443/client
- Главная страница открывает клиентский кабинет.

Пароль администратора задаётся при развёртывании и хранится отдельно от репозитория. Клиенты самостоятельно регистрируются по имени, email и паролю. Email служит логином: отправка писем и подтверждение email не настроены. Восстановление забытых паролей требует обращения к администратору; автоматического сброса пока нет.

## Как связать автомобиль

1. Администратор нажимает «Добавить автомобиль» и вводит VIN, либо клиент добавляет VIN в своём кабинете. Марка, модель и регион необязательны. Версия системы поступает из ByteDepp. Повторный VIN добавить нельзя.
2. При добавлении администратор может выбрать зарегистрированного клиента или оставить автомобиль без клиента. Позже в карточке доступны «Назначить клиента» / «Изменить клиента»: автомобиль виден только выбранному клиенту. Если клиент ещё не зарегистрирован, сначала он создаёт кабинет. Самостоятельно присвоить уже зарегистрированный VIN клиент не может.
3. В разделе «ByteDepp» видны устройства, уже зарегистрированные действующим приложением на сервере ByteDepp.
4. Администратор открывает автомобиль, нажимает «Связать с ByteDepp», выбирает устройство и подтверждает принадлежность клиенту. Устройство с другим VIN привязать нельзя. Устройство без VIN можно выбрать после ручной проверки.
5. Клиент видит текущий доступ к русскому языку и магазину. Статусы обновляются с сервера ByteDepp.

Регистрация VIN сама по себе не доказывает владение автомобилем. Доступ к данным существующего устройства появляется только после подтверждения администратором. Одно устройство нельзя связать с двумя автомобилями. Автомобиль без клиента виден только администратору; его тоже можно связать с ByteDepp. При последующем назначении такого автомобиля клиенту нужно подтвердить принадлежность автомобиля. Назначение и снятие клиента записываются в журнал и не меняют лицензии ByteDepp.

## Что подключено

Источник — `/srv/bytedepp/bytedepp.sqlite3`, таблица `devices`. В контейнер панель получает только этот файл, с доступом для чтения. Поля `device_id`, `vin`, `language_active`, `language_expires_at`, `store_active`, `store_expires_at` и `updated_at` читаются без изменения лицензий, Telegram-привязок или кода сервера ByteDepp.

Клиентам не выдаются device ID, коды привязки, Telegram ID, список чужих автомобилей или учётные данные администратора. Код привязки и Telegram ID не читаются адаптером вообще.

`updated_at` означает изменение записи в ByteDepp, а не текущий онлайн автомобиля. Модель и телеметрия в существующей интеграции не передаются. Версия системы автомобиля теперь читается из `vehicle_software_version` вместе с датой `vehicle_software_reported_at`. Поле добавлено в существующий сервер ByteDepp и принимается как `vehicleSoftwareVersion` в `/api/device/session`. Ручная версия не используется. В Android-приложение добавлена отправка прочитанной версии; источники данных ещё нужно проверить на конкретном автомобиле. VIN в ByteDepp берётся из данных, отправленных самим приложением. Если приложение пока не использует этот сервер лицензий, одного наличия APK в каталоге недостаточно: потребуется проверить его настройки или интеграцию после получения исходников.

При недоступности источника или несовпадении VIN панель показывает проблему и скрывает статусы сервисов от клиента. Реальные автомобили во время разработки не подключались: проверены API, разграничение доступа, чтение базы и веб-интерфейс.

## Развёртывание на текущем сервере

- Код панели: `/srv/fleet-control/app`.
- Контейнер: `app-panel-1`, работает без root, корневая файловая система только для чтения.
- База панели: Docker volume `app_fleet_data`, файл `fleet.sqlite`.
- Панель слушает только `127.0.0.1:3080`. Nginx обслуживает HTTPS на порту 8443.
- Конфигурация Nginx: `/etc/nginx/sites-available/fleet-control`.
- Используется существующий IP-сертификат `/etc/letsencrypt/live/lynk-panel-ip/`. Его обновляет уже настроенный таймер `lynk-certbot-renew.timer`; после обновления Nginx перечитывает сертификат.
- Существующие сервисы на портах 80 и 443 не изменены.

```bash
cd /srv/fleet-control/app
docker compose ps
docker compose logs --tail 100 panel
docker compose up -d --build --wait
```

Не выполняйте `docker compose down -v`: это удалит данные панели. Перед переносом/изменением схемы сохраните согласованную резервную копию базы и `.env`. Для небольшого сервера можно остановить только контейнер панели на время копирования его volume и затем запустить обратно; ByteDepp продолжит работать.

## Локальный запуск

Нужен Node.js 24.14 или новее из ветки 24. Внешних npm-зависимостей нет.

```bash
npm run setup
npm start
npm test
```

`setup` создаёт `.env` и случайный пароль, не перезаписывая существующие настройки. Для локального источника укажите `BYTEDEPP_DB=/путь/к/копии/bytedepp.sqlite3`. Без источника клиентский кабинет и регистрация VIN работают, а панель честно сообщает, что ByteDepp не подключён.

Если источник переведён в режим WAL, смонтируйте также его WAL/SHM-файлы или используйте согласованный SQLite backup: текущее подключение рассчитано на действующую базу ByteDepp с обычным rollback journal. Поддерживаются до 5000 записей устройств за один запрос; для большего числа потребуется пагинация.

## Проверки

`node --test test/portal.test.mjs` проверяет разные сессии клиента и администратора, защиту от запросов с другого сайта, добавление VIN администратором, назначение и снятие клиентов, изоляцию автомобилей между кабинетами, подтверждение владения при связывании и переназначении, запрет несовпадающих VIN, актуальность/сроки лицензий, отсутствие изменений в ByteDepp, восстановление после перезапуска и отключение старых маршрутов APK.

Контракт для разработчика приложения: [integration/BYTEDEPP-API.md](integration/BYTEDEPP-API.md). Серверная часть и Android-код отправки готовы; следующая проверка — реальные значения с автомобиля, передача в `/api/device/session` и отображение в нужном кабинете.

Приём данных приложением доступен по HTTPS: `https://84.21.173.88:8443/api/device/session`. Маршруты сессии устройства и чтения лицензии проксируются в существующий ByteDepp. Проверки Python в `test/test_bytedepp.py` запускаются с `BYTEDEPP_SERVER_SOURCE=/путь/к/обновлённому/bytedepp_server.py` и используют временные базы.
