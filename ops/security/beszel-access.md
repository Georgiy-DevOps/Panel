# Доступ к Beszel через локальный SSH-туннель

Beszel работает на `94.156.114.97:127.0.0.1:8090`: HTTP-порт не опубликован
в интернет. На компьютере администратора используется адрес
`http://127.0.0.1:8090/` и уже настроенная задача Windows `Beszel-tunnel`.
Для туннеля используется отдельная SSH-учётная запись `beszel-tunnel` с ключом,
без shell/sudo и с разрешённым назначением только `127.0.0.1:8090`.

## Если страница открыта, но вход не проходит

Открытая ранее страница сама по себе не подтверждает работоспособность туннеля.
Сначала проверить доступ к API с того же компьютера:

```powershell
Get-ScheduledTask -TaskName 'Beszel-tunnel'
Get-NetTCPConnection -State Listen -LocalPort 8090
Invoke-RestMethod -Uri 'http://127.0.0.1:8090/api/health' -TimeoutSec 5
```

Если локального слушателя нет, проверить действия существующей задачи, наличие
её файлов и журнал. Не восстанавливать удалённые антивирусом файлы и не отключать
защиту, чтобы запустить непроверенный скрипт. После проверки существующей задачи:

```powershell
Start-ScheduledTask -TaskName 'Beszel-tunnel'
```

Повторно проверить API, затем обновить страницу через Ctrl+F5 и войти в Beszel.
Перезагрузка VPS, открытие порта 8090 в интернет и смена пароля для восстановления
остановленного туннеля не требуются.

При исправном API и продолжающейся ошибке входа проверить учётную запись и ошибки
аутентификации в PocketBase. Не выводить из базы поля password/tokenKey, не
запрашивать пароль в чате. Пароль веб-интерфейса Beszel, пароль SSH и Passphrase
приватного SSH-ключа относятся к разным механизмам входа.

Учётные записи Hub (`users`) и PocketBase (`_superusers`) также раздельны.
Смена пароля superuser не меняет пароль входа в Hub: это описано в
[официальной документации Beszel](https://beszel.dev/guide/user-accounts).

## Проверка 18.09.2026

Серверный Beszel работал и отвечал HTTP 200, но задача `Beszel-tunnel` на Windows
не была запущена, локальный порт 8090 отсутствовал. Парольная аутентификация
учётной записи Hub оставалась включённой; изменения её пароля не выполнялись.
После запуска существующей проверенной задачи порт слушает только `127.0.0.1`,
страница и `/api/health` отвечают HTTP 200. Серверы не перезагружались.
