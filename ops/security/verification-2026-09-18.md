На первом сервере сохранены внешние HTTP/HTTPS порты 80, 443 и 8443.
ByteDepp слушает только loopback:8787, контейнер панели опубликован только на
loopback:3080, 1Panel — loopback:30100. Порт Beszel-agent 45876 разрешён только
ранее настроенным адресам мониторинга. Существующий источник мониторинга не удалён
без выяснения его назначения. На втором сервере Beszel слушает loopback:8090;
существующая отдельная SSH-учётная запись для туннеля сохранена.

У ByteDepp включены NoNewPrivileges, ProtectSystem=strict, ProtectHome,
PrivateTmp/PrivateDevices и ограничения ядра. Capabilities удалены: приложение
работает от отдельного пользователя на непривилегированном порту. Nginx больше
не показывает номер сборки (`server_tokens off`). После изменения проверены
конфигурации, перезапуск и health endpoints ByteDepp и панели.

Изменения SSH, фаервола и службы выполнялись с резервной копией и отложенным
откатом. Таймеры отката отменены только после проверки новых подключений и служб.
Обновления настроены через unattended-upgrades; автоматическая перезагрузка
запрещена. Перезагрузку при необходимости согласовать отдельно.

## Оставшиеся ограничения

- Root по ключу пока разрешён; отдельная учётная запись администратора с sudo и
  аппаратный ключ/MFA — дальнейшие изменения, требующие проверки доступа владельца.
- Текущий HTTP API старых клиентов ByteDepp сохранён. Аутентификация устройства и
  обязательный HTTPS требуют согласованного обновления Android-приложения/API.
- Две копии на VPS одного провайдера не защищают от потери обоих серверов.
  Независимое неизменяемое хранилище ещё не подключено.
- Удалённые архивы принимают добавление без удаления отправителем. Их отдельная
  автоматическая очистка пока не настроена; требуется контроль свободного места.
- Результат резервирования доступен в systemd journal и status.json. Доставка
  отдельных оповещений об ошибках резервирования ещё не подключена.
- Проверены файлы приложений, SQLite и конфигурации; загрузочное восстановление
  целого VPS на чистом сервере не испытывалось.
